# mailru-digest

Ежедневный дайджест непрочитанных писем с mail.ru в Telegram.

После удаления приложения Mail.ru из App Store пуш-уведомления о новых письмах перестали приходить. Этот скрипт раз в сутки заходит в ящик по IMAP, собирает список непрочитанных писем и присылает его вам в телеграм.

```
Почта mail.ru — 20.07.2026
Непрочитанных: 4

1. Госуслуги 20.07 09:14
Начислен налог на имущество

2. Тинькофф 20.07 08:02
Выписка по счёту за июнь

3. noreply@hh.ru 19.07 22:40
5 новых вакансий по вашему запросу
```

## Особенности

- **Письма не помечаются прочитанными** — используется `BODY.PEEK`, ящик остаётся ровно в том состоянии, в каком был.
- **Без зависимостей** — только стандартная библиотека Python 3.8+. Никакого `pip install`.
- **Секреты не в коде** — всё в `config.env`, который исключён из git.
- **Ошибки не теряются** — если IMAP недоступен или пароль неверный, вы получите об этом сообщение в телеграм.

## Установка

### 1. Скачать

```bash
git clone https://github.com/FolloW12587/mailru-digest.git
cd mailru-digest
```

### 2. Пароль для внешнего приложения mail.ru

Обычный пароль от ящика для IMAP **не подойдёт** — mail.ru требует отдельный.

1. Откройте [id.mail.ru/security](https://id.mail.ru/security)
2. Раздел **«Пароли для внешних приложений»** → создать новый
3. Скопируйте выданную строку — показывается она один раз

### 3. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, следуйте инструкциям — получите токен вида `12345678:AAF...`
2. **Напишите своему новому боту любое сообщение.** Без этого бот не имеет права писать вам первым, и скрипт получит ошибку `chat not found`.
3. Узнайте свой `chat_id`: напишите [@userinfobot](https://t.me/userinfobot), он ответит числом.

### 4. Конфигурация

```bash
cp config.env.example config.env
chmod 600 config.env   # читать может только ваш пользователь
```

Откройте `config.env` и заполните:

| Переменная | Описание |
|---|---|
| `MAIL_USER` | Полный адрес ящика, например `ivan@mail.ru` |
| `MAIL_PASSWORD` | Пароль для внешнего приложения из шага 2 (не основной!) |
| `TELEGRAM_TOKEN` | Токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | Ваш числовой ID от @userinfobot |
| `MAX_MESSAGES` | Сколько писем максимум показывать. По умолчанию `40` |
| `SEND_IF_EMPTY` | `true` — присылать «непрочитанных нет», подтверждая что скрипт жив. `false` — молчать |

### 5. Проверка

```bash
python3 digest.py
```

Дайджест должен прийти в телеграм сразу. Если что-то не так — смотрите раздел «Если не работает».

### 6. Ежедневный запуск

**macOS (launchd):**

```bash
cp com.example.mailru-digest.plist.example ~/Library/LaunchAgents/com.example.mailru-digest.plist
```

В скопированном файле замените `YOUR_USERNAME` на имя вашего пользователя (`whoami`) и поправьте путь к интерпретатору (`ls /opt/homebrew/bin/python3.*`). Лучше указывать версионированный путь вроде `/opt/homebrew/bin/python3.12`: ссылку `python3` без версии Homebrew может удалить при обновлении. Время запуска задаётся в `StartCalendarInterval` — по умолчанию 9:00.

```bash
launchctl load ~/Library/LaunchAgents/com.example.mailru-digest.plist
```

После любой правки плиста:

```bash
launchctl unload ~/Library/LaunchAgents/com.example.mailru-digest.plist
launchctl load   ~/Library/LaunchAgents/com.example.mailru-digest.plist
```

**Linux (cron):** `crontab -e`, затем строка для запуска в 9:00:

```
0 9 * * * /usr/bin/python3 /path/to/mailru-digest/digest.py >> /path/to/mailru-digest/digest.log 2>&1
```

## Если не работает

| Симптом | Причина |
|---|---|
| `AUTHENTICATIONFAILED` | Используется основной пароль вместо пароля для внешнего приложения. Либо в настройках ящика отключён доступ по IMAP |
| Telegram: `chat not found` | Вы не написали боту первым, или неверный `TELEGRAM_CHAT_ID` |
| Telegram: `Unauthorized` | Неверный `TELEGRAM_TOKEN` |
| Ничего не приходит по расписанию | Mac спал или был выключен в назначенное время. Проверьте `digest.log` и `launchctl list \| grep mailru` |
| `launchctl list` показывает код `78` | launchd не может запустить интерпретатор — путь к python в плисте больше не существует (например, после `brew upgrade`). Проверьте `launchctl print gui/$(id -u)/<label>` и поправьте путь |
| `Operation not permitted` в `digest.log` | macOS не даёт этому интерпретатору доступ к папке со скриптом (`~/Documents`, `~/Desktop`). Выдайте ему доступ в «Конфиденциальность и безопасность» или перенесите скрипт в другую папку |
| `Нет файла конфигурации` | Не выполнен `cp config.env.example config.env` |

Все запуски по расписанию пишут вывод в `digest.log` рядом со скриптом.

## Ограничения

- Компьютер должен быть включён в момент запуска. launchd выполнит пропущенную задачу после пробуждения из сна, но если машина была выключена весь день — дайджест за этот день не придёт. Для независимости от компьютера скрипт переносится на любой VPS или в GitHub Actions.
- Читается только папка «Входящие».

## Безопасность

`config.env` содержит пароль от почты и токен бота. Он добавлен в `.gitignore` — **не коммитьте его**. Если пароль или токен всё же попал в публичный репозиторий, отзовите их: пароль для внешнего приложения удаляется на [id.mail.ru/security](https://id.mail.ru/security), токен бота — командой `/revoke` у @BotFather.
